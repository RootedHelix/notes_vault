## Core Model

The main idea of Hollix is as follows: create a holographic display using single sided peppers ghost effect with an angled piece of glass. That is it, that simple. However after this core goal is completed I plan to expand the functionality of the device. Currently here is the hardware: 
[[Hollix Prototype Hardware]]

The Display Module will be powered at 1000 nits as this is the main lever in achieving a clear hologram. The supporting hardware such as the backlight driver will be necessary components to configure.

## Daily Log
### 03.04.25

There have been two streams of progress so far in the project. Firstly I started out with my research in learning the basics of how the software interacts with the hardware through various firmware programs on the stm32 MCU. The programs consist of timers, loggers, ring buffers, watchdog timers, and application handlers. One other aspect worth mentioning is the abstraction of project files from the generated HAL that is provided from CubeMX. At first I made the mistake of grouping all the files together within the constructed folders, but then realized that the application files should be withdrawn and placed in their own directory. I've learned a copious amount of material from basic hardware/electronics to the programming patterns that arise within embedded systems. This Concluded phase 1 of the firmware development.

Secondly, more closely related to the Hollix project I have delved into research regarding compatablity between different parts. For instance, when looking for the display module I had to make sure that the specific connector from the display would match the MCU's compatibility standards. Another example includes how many mAh of current that the Display needs to maintain through the display driver so 1000 nits can be hit. Furthermore, the display can't exceed a certain voltage / current without causing damage. These are only a few of the compatibility specifications that were found and researched, but to summarize each component of the system needed to be analyzed with scrutiny to determine whether it would fit the physical and electrical requirements for the system. The research concluded phase 1 of the hardware development.

#### AI Reformatting

The first phase focused on understanding and implementing foundational embedded firmware architecture on the STM32 platform.

This included development of:

- Timer systems
    
- Logging infrastructure
    
- Ring buffer implementation
    
- Watchdog timer management
    
- Application-layer handlers
    
- State-based application control
    

A significant architectural milestone was restructuring the project layout generated by STM32CubeMX. Initially, application logic and HAL-generated files were grouped together. This proved suboptimal.

The project was refactored to:

- Separate application-layer code from HAL-generated drivers
    
- Isolate firmware modules into independent directories
    
- Establish clearer abstraction boundaries
    

This improved modularity, maintainability, and scalability — aligning the project structure with professional embedded development practices.

This work concluded **Phase 1 of firmware development**, resulting in a reusable embedded systems foundation.
